## Where the live results are

`validation-results.json` (same directory) **is** the report: machine
generated, never hand-edited, produced by `tools/validate_dossier.py`.
Its `spec_debt`, traceability, and every other check are always current
as of the last regeneration — there is no second copy to keep in sync.

**Who regenerates it, and when:** the lead, as a fixed step of the
standard bone-close sequence (see `continuum-lead-loop` convention),
after `tools/generate_traceability.py`, whenever a merged bone could
move any validator-visible state (plan.md, RFCs, schemas, `.bones`
state, corpus inventory, ...). It is not regenerated per-commit or by
CI; it is regenerated by whoever closes the bone that changed the
checked state, before that close lands.

**How:** scratchpad, then copy over — never redirect
`validate_dossier.py`'s stdout directly onto `validation-results.json`
with a bare `>`:

```bash
cd notes/plan
uv run --with jsonschema python3 tools/validate_dossier.py > /tmp/validate-dossier-out.json
cp /tmp/validate-dossier-out.json validation-results.json
```

A direct `python3 tools/validate_dossier.py > validation-results.json`
truncates the destination to zero bytes *before* the process starts
writing. The validator's own `empty_files` check scans every file in the
dossier tree, including `validation-results.json`, while it runs — so a
direct redirect makes the run fail against its own not-yet-written
output file. Write to a scratch path first, confirm the run's `status`
is `"pass"`, then `cp` the scratch file over the committed one.

To check current status without touching the committed file, run the
same command and read stdout directly; nothing requires copying it over
`validation-results.json` unless the result is meant to become the new
committed baseline.

## Reproduction

From `notes/plan/` with Python 3.11+ and `jsonschema` installed (or via
`uv run --with jsonschema`, as above):

```bash
python3 tools/generate_traceability.py
python3 tools/validate_dossier.py
python3 tools/generate_manifest.py
```

A successful validator run emits JSON with `"status": "pass"`. The
manifest generator refreshes `MANIFEST.md` and `SHA256SUMS.txt`.
